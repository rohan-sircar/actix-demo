# User Profile System

## Overview

Add a user profile system with public profiles, editable fields (bio, display name, location, website, social links), and OpenAPI schema support.

### 2. `src/models/users.rs` — newtype wrappers + models

Newtypes (all `DieselNewType` for Diesel compatibility):

`Bio` uses a custom manual validator (not `Validator` derive) with `new()`, `inner()`, and custom `Deserialize`:

```rust

impl Bio {
    const MAX_CHARS: usize = 500;
    pub fn new(value: String) -> Result<Self, String>;

```

Other newtypes use `Validator` derive with `line(char_length(max = N))`.

### 3. `src/actions/users.rs` — profile actions

- `get_profile(user_id, conn) -> Result<Option<Profile>, DomainError>` — fetch profile, returns None if not found
- `upsert_profile(upsert: UpsertProfile, conn) -> Result<Profile, DomainError>` — INSERT ... ON CONFLICT (user_id) DO UPDATE
- `get_public_profile(user_id, conn) -> Result<PublicProfile, DomainError>` — fetch and convert to PublicProfile, returns 404 if not found

### 4. `src/routes/users.rs` — route handlers

| Function | Method | Path | Auth | Description |
|----------|--------|------|------|-------------|

Routes wired under existing scopes:

OpenAPI schemas registered: `Profile`, `PublicProfile`, `UpdateProfile`, `UpsertProfile`.

## Notes

- `Display` impl not needed on newtypes — they're just `String` wrappers and won't be logged
- `serde(skip_serializing)` not needed on profile fields — all are serializable
- `UpdateProfile` uses `Option<Newtype>` so clients can send `null` to clear or omit to leave unchanged
- `UpsertProfile` combines user_id + fields for the upsert action (avoids separate parameter)
- `get_user_profile` returns an empty/default `PublicProfile` if no profile row exists (no 404)
- `get_public_profile` returns 404 if no profile row exists for the given user_id
- `Bio` custom validator rejects strings exceeding 500 characters (char count, not byte count)
- `Profile` derives `Identifiable` following the convention of main domain entities (like `User`)
- `created_at`/`updated_at` are `NOT NULL` in the migration to avoid `Nullable` in the model
